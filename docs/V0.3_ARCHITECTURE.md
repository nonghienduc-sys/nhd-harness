# v0.3.1 Architecture

v0.3 adds a project-scoped context engine beside the existing workstation bridge. The chat is not the source of truth: each project persists authoritative transactional state in `<project-root>.nhd/state.sqlite`, with readable JSON, Markdown and JSONL projections.

The existing global workstation database continues to hold OAuth, pending confirmations, global audit and file indexing. Project state holds decisions, document maps, dependency edges, edit sessions and QA results. Existing MCP tools remain compatible. Document-node identity is `(document_id, id)`, so independent DOCX files can each contain `article:1` without colliding.

DOCX files are parsed from OOXML into logical nodes. Anchors use `w14:paraId` first, then normalized headings and fingerprints. The Context Planner retrieves only the requested node, graph-related nodes, decisions and bounded search evidence.

Semantic edits are previewed, hash-bound and backed up before apply. The editor builds, ZIP-validates and structurally maps a temporary DOCX before replacing the original; a failed map commit restores the backup. Closed DOCX files use OOXML editing; live Word editing remains an Office Companion extension point and must reject unsaved conflicts.
