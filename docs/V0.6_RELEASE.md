## v0.6 features

### Workstation Router

`workstation_plan` provides planning-only route selection. It never executes the task and never grants permissions. Route priority is:

1. structured MCP/API,
2. Office structured/live APIs,
3. Browser DOM/CDP,
4. Windows UI Automation,
5. verified visual fallback only when explicitly allowed.

The planner returns observations, confirmation requirements, verification contracts and bounded recovery policy.

### Verify + Recovery

v0.6 adds first-class verification and recovery primitives:

- `WorkstationVerifier`
- `RecoveryController`
- `RecoveryStateMachine`
- structured `ActionReceipt`

Execution states are explicit: `planned -> observed -> executing -> verifying -> verified/recovering/failed`.

Ambiguous write/destructive actions are never automatically repeated.

### Browser post-condition verification

`browser_wait_for` supports machine-checkable conditions:

- URL equals/contains
- title equals/contains
- visible text contains
- inspected control value equals
- no-navigation assertion

Browser selectors are identity-checked before click/fill. If the DOM control changes after inspection, the action is rejected and a fresh inspect is required.

### Verified Browser actions

`browser_click_verified` and `browser_fill_verified` execute the action exactly once and then verify the expected post-condition.

If the outcome is ambiguous:

- the click/fill is not repeated,
- only bounded DOM re-inspection is allowed,
- the result is returned as failed/ambiguous with an action receipt.

`browser_fill_verified` receipts do not echo the filled text; only character count and verification evidence are recorded.

### Runtime capability snapshot

The router derives current capabilities from actual runtime state rather than assuming all features are available.

Examples:

- Word Live Write is routable when Word + Office Companion + write permission are available.
- Excel/PowerPoint/Outlook Live Write remain unavailable in v0.6.
- Emergency Stop disables active execution/navigation capability.
- Missing Browser executable falls back to Desktop UIA when available.

## Test harness note

PowerShell `Get-Content/Set-Content` must not be used to round-trip Unicode source/test fixtures containing Vietnamese text. During v0.6 development this created false Project/Document failures by corrupting strings such as `CHƯƠNG`, `Điều`, and `Khoản`.

Use Node `fs.readFileSync(..., 'utf8')` / `fs.writeFileSync(..., 'utf8')` for source/test transformations.
