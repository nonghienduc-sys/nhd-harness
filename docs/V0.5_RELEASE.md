## Office Live Write

v0.5 adds:

- `office_live_preview_edit`
- `office_live_apply_edit`

Current live-write scope is intentionally narrow: Word `replace_selection` only.

Workflow:

1. user selects non-empty Word text,
2. preview reads exact document path/name/range/text,
3. preview stores a selection fingerprint and returns a one-time token,
4. apply rereads Word and rejects if the selection changed,
5. confirmed replacement is applied,
6. Word is reread and exact resulting selection text is verified.

Live smoke test:

- initial selection: `beta`, range 6..10
- replacement: `BETA_OK`
- verified selection after apply: `BETA_OK`, range 6..13
- reused confirmation token: rejected

## Office Companion authentication

Office Companion now requires `x-workstation-companion-secret` on both `/status` and `/action`.

Server behavior verified:

- no secret -> HTTP 401
- wrong secret -> HTTP 401
- correct shared staging secret -> HTTP 200

Electron passes a single ephemeral `WORKSTATION_COMPANION_SECRET` to the server and Office Companion, and its availability probe sends the same secret header.

The secret is not persisted in dashboard config output.

## ChatGPT connector schema cache

Important distinction:

- `http://127.0.0.1:39100/api/tools` reports the live runtime registry and currently reports 62 tools.
- A ChatGPT conversation whose MCP connector function schema was mounted before the v0.5 deployment can remain pinned to the older schema count for the lifetime of that conversation.

During this deployment the current conversation's connector resource still exposed 52 function schemas after the production runtime had been verified at 62 tools.

This is not a Workstation MCP registry failure. The current `/mcp` endpoint is stateless Streamable HTTP: each POST creates a short-lived `McpServer`, connects, handles one request, and closes. There is no persistent client session in which `notifications/tools/list_changed` can update an already-mounted ChatGPT harness schema.

For a ChatGPT client to expose the nine newly added functions to the model, use a newly mounted connector session (normally a new chat after the connector has re-read the MCP tool list, or reconnect the custom connector and then start a fresh chat if the client still uses the previous schema cache).

Do not restart production merely to try to fix this client-side schema cache; server restarts were already proven not to change the function set mounted into the existing conversation.
