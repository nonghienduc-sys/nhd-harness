# NHD MCP v0.8 Handoff — Durable Memory Map + Long-Running Tasks

Updated: 2026-09-13

## Stable production baseline

Production is **v0.7.0 / 69 tools**.

Do not modify production `dist` while developing v0.8.

## v0.8 objective

Add durable task state that can survive Workstation MCP restarts without turning memory into a raw data warehouse or silently resuming ambiguous actions.

Target model:

`OWNER TASK -> DURABLE RUN -> PLAN/STEP -> VERIFY -> RECEIPT -> CHECKPOINT -> NEXT STEP`

A run may span multiple MCP requests and process restarts, but no interrupted executable action may be repeated automatically.

## Memory principle

**Memory is a map to evidence, not the evidence warehouse.**

Durable run memory may contain:

- short checkpoint summaries,
- next-action notes,
- references to files/documents/projects/messages/pages,
- fingerprints / stable IDs,
- receipt IDs,
- bounded unresolved items.

It must not persist:

- full terminal stdout/stderr,
- full web pages,
- full document bodies,
- credentials/tokens/passwords,
- arbitrary environment dumps,
- hidden model reasoning.

## Milestone A — durable task state machine

Implement `TaskRunManager` backed by the Workstation SQLite store.

States:

- `planned`
- `running`
- `waiting_confirmation`
- `paused`
- `completed`
- `failed`
- `cancelled`
- `expired`

Required invariants:

1. random unguessable run IDs,
2. explicit objective,
3. max step budget,
4. max runtime budget,
5. one active step maximum,
6. verified completion metadata only,
7. bounded checkpoint summary,
8. bounded reference map,
9. no implicit cross-run sharing,
10. interrupted in-flight steps become `interrupted` and run becomes `paused` after process restart,
11. interrupted steps are never automatically repeated,
12. terminal/browser/write receipts are referenced by ID rather than copied wholesale.

## Milestone B — durable reference map

Reference types should be small and typed, e.g.:

- `file`
- `document`
- `project`
- `url`
- `message`
- `receipt`
- `other`

Each reference stores only bounded metadata:

- reference id,
- label,
- type,
- location/stable identifier,
- optional fingerprint,
- created timestamp.

## Milestone C — checkpoints

A checkpoint contains:

- bounded summary,
- next action,
- sequence number,
- updated timestamp.

Checkpointing is explicit; a task is not considered durable merely because a model mentioned something in chat.

## Milestone D — MCP planning/state tools

Only after persistence tests pass, expose planning/state-management tools. These tools should not execute workstation actions by themselves.

Suggested surface:

- `task_run`
- `task_run_step`
- `task_run_reference`
- `task_run_checkpoint`

Execution remains routed through existing v0.6/v0.7 tools.

## Milestone E — bounded agent runner

Only after the durable state layer is stable, add a bounded agent runner that can chain routed actions under explicit budgets.

Hard limits:

- max steps,
- max runtime,
- stop on ambiguity,
- no silent external side effects,
- confirmation remains mandatory where existing tool policy requires it,
- Emergency Stop pauses/cancels active runs,
- every completed action must have verification evidence / receipt linkage.

## Recovery rule

If the MCP process restarts while a run has an active step:

- mark the step `interrupted`,
- clear it from active execution,
- mark the run `paused`,
- require a new observation/preview before any retry,
- never infer that the interrupted action either succeeded or failed.

## First implementation step

Create `src/task-runtime.ts` with SQLite-backed durable run, step, checkpoint and reference state. Add restart-recovery tests before any MCP tool exposure.
