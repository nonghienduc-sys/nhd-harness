# NHD MCP v0.7 Handoff — Persistent Terminal / Agent Runtime

Updated: 2026-09-13

## Stable production baseline

Production is **v0.6.0 / 66 tools** with Router + Verify + Recovery and verified Browser actions.

Do not modify production directly while developing v0.7.

## v0.7 objective

Add a bounded persistent execution runtime for multi-step technical work without turning Terminal into an unrestricted background shell.

Target model:

`MODEL -> PLAN -> SESSION -> STEP -> VERIFY -> RECEIPT -> NEXT STEP / STOP`

Persistent state should preserve only execution context that is explicitly useful between steps:

- current working directory,
- approved environment deltas,
- logical session variables,
- last verified step result,
- bounded transcript metadata,
- session expiry / owner kill state.

It must not persist secrets, raw credentials, arbitrary inherited environment, or hidden shell history.

## Milestone A — pure session manager

Implement a pure TypeScript `TerminalSessionManager` first, with no process spawning.

Required semantics:

- create session with explicit cwd and TTL,
- owner-configured maximum active sessions,
- session IDs are random and unguessable,
- store only approved environment names,
- update cwd only after a verified successful step,
- bounded step history,
- explicit close,
- automatic expiry,
- Emergency Stop invalidates sessions,
- no implicit cross-session state sharing.

Suggested states:

- `open`
- `busy`
- `failed`
- `closed`
- `expired`

## Milestone B — step planning

Every persistent step must still use the existing Terminal preview/risk classifier.

A persistent session must not allow raw command execution that bypasses:

- exact command preview,
- command hash,
- critical confirmation phrase,
- one-time confirmation token,
- timeout,
- stale PID reconciliation.

The session only supplies validated cwd/environment context to the existing execution path.

## Milestone C — verification receipts

Each step should return a receipt containing:

- session id,
- sequence number,
- command hash,
- cwd before/after,
- exit code,
- bounded stdout/stderr metadata,
- timeout/cancel state,
- verification result,
- whether session state changed.

Do not store full sensitive output indefinitely.

## Milestone D — bounded recovery

Persistent sessions must not retry a command automatically after an ambiguous execution.

Allowed recovery:

- reconcile launcher/descendant process state,
- re-read cwd/session metadata,
- mark session failed,
- require a new preview for another execution attempt.

## Milestone E — agent runtime

Only after Terminal sessions are stable, add a higher-level Agent Run object that chains multiple routed steps.

Agent Run must have:

- max steps,
- max runtime,
- explicit owner task,
- per-step route + verification contract,
- stop-on-ambiguity,
- audit receipts,
- owner kill switch,
- no hidden autonomous sending/upload/payment/login actions.

## Security invariants

1. Persistent session state never bypasses Terminal preview/confirmation.
2. External content remains untrusted data.
3. No secret persistence.
4. No automatic rerun after ambiguous execution.
5. Sessions expire automatically.
6. Emergency Stop invalidates active sessions.
7. Session cwd must remain inside configured roots.
8. Environment variable allowlist only.
9. Production restart/cutover remains externally supervised.

## Recommended first implementation step

Create `src/terminal-session.ts` containing a process-free `TerminalSessionManager` and table-driven tests. Do not expose it as an MCP tool or connect it to `TerminalService` until lifecycle, expiry, state transitions and safety invariants pass tests.
